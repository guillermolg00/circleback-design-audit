---
title: Menus per object
description: The same object has three different menus depending on where you open it.
---

<Sev level="high" />

<Finding>
  <What>
    The “…” menu on an owned meeting: Rename, Automations, Copy notes, Copy transcript, Delete. Right-click in the list: Share, Tags, Automations, Delete. On a shared meeting: Copy notes and Remove. “Delete” and “Remove” name the same action.
  </What>
  <Why>
    The user learns one menu and runs into another. Share and Tags only exist in the context menu; Rename and Copy transcript only in “…”. Nothing explains why.
  </Why>
  <Linear>
    The same set of actions, in the same order and with their shortcuts, in the context menu, in “…”, and in ⌘K on the selection.
  </Linear>
  <Proposal>
    One set of actions per object, in the same order everywhere. Anything that doesn’t apply appears disabled with the reason (“Only the owner can rename”).
  </Proposal>
</Finding>
